# Обязательное сохранение каждого этапа

Прямое требование Анатолия от 15 октября 2026 года: сохранять каждый этап отдельным файлом здесь или в репозитории, чтобы не потерять работу.

## Состав сохранения

1. Отдельный отчёт `docs/stages/STAGE_XX_Название.md`: цель, выполненные изменения, точные файлы, доказанные проверки, визуальные материалы, ограничения, следующий шаг.
2. Версия исходников в Git с идентификатором коммита, если доступ на запись в подключённый репозиторий работает. Кэши импорта, временные данные и исходные большие архивы не добавлять в историю исходников.
3. Законченный и проверенный ZIP контрольной точки для содержательных изменений проекта; исходные архивы и последнюю рабочую версию не перезаписывать.
4. Изображения и последовательности/видео, относящиеся именно к сохранённой версии. Большие материалы можно хранить отдельным архивом, явно связав его с этапом.
5. SHA-256 архива, результат проверки CRC и возможность распаковки. При передаче проекта проверять нужные для запуска файлы и импорт/запуск после распаковки.
6. В сообщении пользователю — ссылка на отчёт, версию и/или файлы. Локальное сохранение, успешную отправку на GitHub и публикацию среды обозначать раздельно.

## Защита от потерь

- Работа ведётся в существующей изолированной рабочей копии. Git worktree создавать только по прямому запросу.
- Отчётный файл не заменяет сохранение изменённых исходников. Коммит не считается резервной копией на GitHub до успешной отправки и проверки удалённой ссылки.
- Исходный релиз `transfer-01` и `/workspace/shashlik-transfer/` остаются основой восстановления.
- Локальные ZIP не обещают сохранность вне текущей среды. До окончания этапа нужно указать пользователю, где реально находится резервная копия, и сообщить о неудачной отправке.
- При невозможности отправки на GitHub сохранить локальные исходники, проверенный архив и отчёт, дать файлы пользователю и объяснить точное ограничение. Не запрашивать пароль или токен в чате.
- После существенной самостоятельной правки сохранять промежуточную версию, даже если большой этап ещё не закончен. Статус «промежуточная» указывать явно.

Первое сохранение после этого требования должно включать Graphics 06, ContactFix 01, полный план и новые требования к качеству. Планирующий отчёт также сохраняется отдельным документом; основной визуальный этап при этом не считается выполненным.
